# 비즈니스 관련 정보
  - 목표 사용자: 국내외 여행을 준비하거나 여행중인 사용자
  - 비즈니스 목표: 1000명이 동시 접속하여 사용할 수 있어야 함

# 기술 제약사항
  - 플랫폼 우선순위: 안드로이드 및 iOS용 앱
  - 인프라 제약:
   * 프론트엔드: Flutter + Dart
   * Android 전용: Kotlin, Gradle, Android 권한 백그라운 API
   * iOS 전용: Swift, Xcode, iOS 권한 백그라운드 API
   * 지도: Google Maps Flutter 연동
   * 위치: Flutter 플러그인 우선, 부족시 플랫폼 전용(Kotlin/Swift) 브리지
   * 테스트: flutter analyze, flutter test, Android/iOS 실기기 테스트

# 프로젝트 관리
  - 일정: 2일 내에 핵심 기능 완성
  - 팀 구성: 1인 개발
  - 예산: 1인 개발에 준하는 예산

# 사용자 경험
  - 사용자 페르소나: 주 사용자별 상세 시나리오는 생략
  - 접근성: 사용자 인증을 통해 설치된 앱을 접근

# 추가 입력

## 1. 인증방식 

- 로컬 인증방식
  - 앱 실행, 잠금해제시 활용
  - 방법: 생체(지문,얼굴)인식, PIN, 비밀번호 등
- 원격 인증방식
  - 공통 인증서버(Firebase Authentication) 활용
  - Android 로그인: Google계정, 이메일 링크
  - iOS 로그인: Apple 계정, Google 계정, 이메일 링크
  - 사용자 식별: Firebase uid
  - 로그인 상태 유지: Firebase SDK
  - 사용자 데이터 연결: 모든 데이터에 uid 저장, 구글 드라이브나 SNS 공유시 활용

## 2. 앱 설정
- 앱 설정 화면을 통해 앱 제어 기능을 상세히 설정

## 3. 문서 갱신
- 독립적인 서브에이전트를 이용해 docs 디렉토리 내의 문서들을 비교 검토하여 적합성 여부를 확인하고 차이가 있다면 문서를 업데이트해줘
