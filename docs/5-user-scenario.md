## 1. 시나리오 목적

여행 준비부터 여행 중 기록, 과거여행 조회와 공유까지 사용자가 앱을 이용하는 대표 흐름을 정의한다.

세부 데이터와 기능 기준은 [도메인 정의](3-domain-definition.md)와 [PRD](4-prd.md)를 따른다.

## 2. 공통 조건

- 사용자는 Android 또는 iOS에 앱을 설치한다.
- 앱 실행 시 설정된 로컬 인증을 통과해야 로컬 자료에 접근할 수 있다.
- 최초 로그인이나 원격 기능 사용 시 Firebase Authentication으로 인증한다.
- 국내 여행은 도시, 해외 여행은 나라를 기준으로 여행 범위를 정한다.
- 위치·미디어·메시지 권한은 실제 기능을 사용할 때 필요한 범위만 요청한다.
- 앱이 백그라운드에서 연속 10분 이상 지난 뒤 다시 열리면 로컬 인증을 요구한다.

현재 구현 상태는 Android 로컬 저장·로컬 인증·GPS·사진 메타데이터·날씨·카카오지도 범위까지다. Firebase 클라이언트 인증, 독립 메모, 외부·주변 기기 공유와 iOS 실기기 흐름은 시나리오 정의만 완료된 후속 범위다.

## 4. 상세 시나리오

### US-01 앱 설치 후 최초 인증

#### 시작 조건

사용자가 앱을 처음 실행하거나 로그아웃 상태로 앱을 실행한다.

#### 기본 흐름

1. 앱이 로컬 인증 설정을 확인한다.
2. 사용자가 지문·얼굴 인식, PIN 또는 비밀번호로 잠금을 해제한다.
3. 원격 기능을 사용하는 경우 인증 화면을 표시한다.
4. Android에서는 Google 계정 또는 이메일 링크를 선택한다.
5. iOS에서는 Apple 계정, Google 계정 또는 이메일 링크를 선택한다.
6. Firebase Authentication이 인증을 완료하고 `uid`를 발급한다.
7. 앱은 로그인 상태를 유지하고 여행 생성 화면을 표시한다.

현재 Flutter 앱은 1~2단계의 로컬 인증과 로컬 자료 접근까지 구현되어 있으며, 3~7단계는 Firebase 클라이언트 연동 후 적용한다.

#### 예외 흐름

- 로컬 인증에 실패하면 자료 화면에 접근시키지 않고 다시 인증할 수 있게 한다.
- 원격 인증이 취소되거나 실패하면 오류를 표시하고 인증 방식을 다시 선택하게 한다.
- 네트워크가 없으면 이미 인증 상태가 유지된 사용자는 로컬 자료를 조회할 수 있게 한다.

### US-02 여행 생성

#### 시작 조건

사용자가 인증을 완료하고 여행 생성 화면에 진입한다.

#### 기본 흐름

1. 사용자가 국내 또는 해외 여행을 선택한다.
2. 국내 여행이면 도시를, 해외 여행이면 나라를 선택한다.
3. 여행 시작일과 종료일을 입력한다.
4. 앱이 현지 시간대와 여행 범위를 표시한다.
5. 사용자가 저장하면 여행 식별자를 생성한다.
6. 이후 수집되는 이동경로와 활동 기록을 해당 여행에 연결한다.

#### 완료 상태

여행 목록에서 여행 기간과 도시 또는 나라를 확인할 수 있다.

### US-03 여행 중 자료 자동 수집

#### 시작 조건

진행 중인 여행이 있고 사용자가 필요한 권한을 허용했다.

#### 기본 흐름

1. 앱은 설정된 간격으로 GPS 위치를 수집한다.
2. 사진 메타데이터를 사진첩에서 선택해 촬영 시각·장소·파일 정보를 저장한다.
3. 현지 지도 저장 장소, 결제 장소, 사진·동영상 장소, 노트 작성 장소를 우선 관련 장소로 연결한다.
4. 검색 자료는 시각, 장소, 종류, 제목, 요약, 출처와 함께 저장한다.
5. 결제 자료는 확인 가능한 범위에서 현지 시각, 가게, 구매 내용을 메모화한다.
6. 날씨는 WWIS 도시 예보를 저장하고, 당일 예보가 없으면 현재 날씨를 보완 조회한다.
7. 각 자료를 활동 기록으로 만들고 여행 식별자와 연결한다.

#### 예외 흐름

- 위치 정확도가 낮으면 정확도와 연결 상태를 함께 저장한다.
- 파일이나 메타데이터를 읽지 못하면 실패 상태를 남긴다.
- 권한이 없으면 해당 자료만 수집하지 않고 다른 기능은 계속 제공한다.

### US-04 메모 작성과 첨부

#### 기본 흐름

1. 사용자가 여행 또는 날짜별 경로 화면에서 메모 작성을 선택한다.
2. 제목과 내용을 입력한다.
3. 제목을 입력하지 않으면 현지 시각 기준 날짜와 시간을 제목으로 사용한다.
4. 사진첩 또는 폴더에서 사진·동영상·파일을 선택해 첨부한다.
5. 배경색과 글꼴을 설정한다.
6. 저장하면 메모를 활동 기록과 장소에 연결한다.
7. 사용자는 저장된 메모와 첨부파일을 다시 수정할 수 있다.

### US-05 날짜별 경로 조회

#### 시작 조건

사용자가 여행과 날짜를 선택한다.

#### 기본 흐름

1. 앱이 해당 날짜의 GPS 위치 기록을 시간순으로 불러온다.
2. 현재 Android는 카카오지도인 현지 지도에 이동경로를 표시한다. 국외 Google Map 전환은 후속 범위다.
3. 경로 주변 활동 기록을 사진, 동영상, 메모, 결제, 날씨 등의 아이콘으로 표시한다.
4. 화면 상단에 날씨와 주요 기록을 요약한다.
5. 사용자가 아이콘을 선택한다.
6. 앱이 자료 종류에 맞는 상세 정보를 팝업으로 표시한다.

### US-06 과거여행 조회와 편집

#### 기본 흐름

1. 사용자가 과거여행 조회 메뉴를 연다.
2. 앱이 여행 기간과 도시 또는 나라를 목록으로 표시한다.
3. 사용자가 여행을 선택한다.
4. 앱이 전체 기간의 동선을 현지 지도에 표시한다.
5. 날짜별 동선을 서로 다른 색으로 표시한다.
6. 사용자가 특정 날짜의 동선을 선택하면 날짜별 경로 조회 화면을 연다.
7. 사용자는 선택, 수정, 삭제 메뉴를 사용할 수 있다.

현재 Android에서는 저장된 전체 GPS 경로를 날짜별 색상의 네이티브 폴리라인으로 표시하고, 기록 카드와 지도 위치에 동일한 순번을 표시한다. 날짜별 독립 조회 화면 전환은 후속 범위다.

지도는 진행 중 여행이면 현재 위치와 도시 규모, 미래 여행이면 국가·도시 중심과 도시 규모, 과거 여행이면 저장된 경로와 도시 규모를 기준으로 처음 표시한다. 사용자는 핀치로 확대·축소하고 한 손가락 드래그로 이동하며, 내 위치 버튼으로 현재 위치 중심으로 되돌린다.

#### 사진 메타데이터 흐름

1. 사용자가 여행 상세의 사진 화면을 연다.
2. 앱이 사진 접근 권한을 요청하고 여행기간 사진을 grid로 표시한다.
3. 사용자가 필요한 사진을 선택해 현지 촬영시각·장소·원본 파일 경로 메타데이터를 저장한다.
4. 사용자가 삭제하면 메타데이터와 앱 표시 대상만 삭제하고 원본 사진은 유지한다.

#### 삭제 흐름

1. 사용자가 삭제를 선택한다.
2. 앱이 삭제 대상과 영향을 받는 자료를 표시한다.
3. 사용자가 삭제를 확인한다.
4. 앱이 정의된 삭제 정책에 따라 자료를 처리하고 결과를 표시한다.

### US-07 여행 공유

#### 기본 흐름

1. 사용자가 여행 목록에서 공유할 여행을 선택한다.
2. 앱이 Google Drive, SNS, 주변 기기 공유 방식을 표시한다.
3. 사용자가 공유 방식을 선택한다.
4. Google Drive 또는 SNS 공유 시 사용자 `uid`와 연동 권한을 확인한다.
5. 주변 기기 공유 시 Wi-Fi 또는 Bluetooth로 통신 가능한 기기를 검색한다.
6. 수신 기기에 동일 앱이 설치되어 있는지 확인한다.
7. 수신 기기가 공유를 동의하면 선택한 여행의 모든 수집 데이터를 전송한다.
8. 수신 기기는 여행 데이터를 저장하고 과거여행 조회 목록에 표시한다.

현재는 `backend/`에 Firebase ID 토큰 검증과 공유 세션 상태 API만 구현되어 있으며, Flutter 앱의 실제 전송과 수신 기기 조회는 후속 범위다.

#### 예외 흐름

- 수신 기기가 동의하지 않으면 전송하지 않는다.
- 연결이 끊기면 전송 상태와 재시도 방법을 표시한다.
- 공유 전 개인정보가 포함된 자료와 전체 데이터 전송 범위를 사용자에게 확인받는다.

### US-08 앱 전체 설정

1. 사용자가 앱 전체 설정 메뉴를 연다.
2. 백그라운드 위치 수집 정책과 배터리 사용 한도를 확인한다.
3. GPS 위치 수집 간격을 설정하고 저장한다.
4. Google Drive와 SNS 공유 연동 정보를 입력하거나 수정한다.
5. 앱은 연동 정보를 일반 메모와 디버그 로그에 기록하지 않는다.

### US-09 권한·네트워크 오류 처리

#### 권한 거부

- 앱은 필요한 기능과 권한 목적을 설명한다.
- 사용자가 권한을 거부하면 해당 수집 기능을 비활성화한다.
- 권한이 필요한 다른 기능에는 영향을 주지 않는다.

#### 네트워크 단절

- 로컬에 저장된 여행과 메모는 가능한 범위에서 계속 조회·작성한다.
- 원격 인증이나 공유 실패는 자료를 버리지 않고 실패 상태로 표시한다.
- 네트워크가 복구되면 사용자가 재시도할 수 있다.

#### 처리 실패

- 실패한 자료의 종류와 처리 결과를 사용자에게 알린다.
- 디버그 모드에서는 안전한 요약 로그를 남긴다.
- 비밀번호, 토큰, 원본 메시지와 개인정보가 포함된 파일 경로는 로그에 남기지 않는다.

## 5. 시나리오 공통 완료 기준

- 사용자는 인증 후 자신의 여행 자료에 접근할 수 있다.
- 여행 자료는 여행 식별자, 현지 시각, 장소와 연결된다.
- 로컬 저장 자료는 네트워크가 없어도 가능한 범위에서 조회된다.
- 지도·자료·공유 기능의 실패가 원본 자료 손실로 이어지지 않는다.
- Android와 iOS에서 권한과 인증 흐름을 각각 확인한다.
- 주요 시나리오는 `flutter test`와 Android·iOS 실기기 테스트로 검증한다.
