## 1. 문서 목적

여행 중 생성되는 자료를 여행 단위로 모아 저장하고, 날짜·시간·장소를 기준으로 조회·공유하는 앱의 MVP 요구사항을 정의한다.

도메인 모델의 상세 기준은 [도메인 정의](3-domain-definition.md)를 따른다.

대표 사용자 흐름은 [사용자 시나리오](5-user-scenario.md)를 따른다.

## 2. 제품 개요

### 2.1 목표 사용자

국내외 여행을 준비하거나 여행 중인 사용자다.

### 2.2 해결할 문제

사진, 동영상, 이동경로, 메모, 결제, 검색 자료, 날씨가 여러 앱에 흩어져 있어 여행의 흐름으로 확인하기 어렵다.

### 2.3 제품 목표

- 여행별 자료를 하나의 기록으로 묶는다.
- 현지 시각과 장소를 기준으로 자료를 연결한다.
- 날짜별 이동경로와 관련 자료를 함께 조회한다.
- 과거여행을 다시 조회하고 다른 기기나 외부 서비스로 공유한다.
- 앱은 1,000명 동시 접속을 목표로 설계한다.

## 3. 범위

### 3.1 MVP 포함 범위

- 로컬 잠금 해제
- 국내 도시 또는 해외 나라 기준의 여행 생성
- 여행 목록과 여행 상세 조회
- Android 카카오지도 기반 GPS 이동경로·기록 위치 마커 조회
- 사진 기간 grid와 사진 메타데이터 저장·숨김
- WWIS 기반 날씨 조회·저장과 당일 현재 날씨 보완
- 선택일자 기준의 로컬 저장
- 백그라운드 위치 수집과 설정 가능한 수집 간격(기본 10분)

다음 항목은 제품 범위에는 포함하지만 현재 Flutter 앱과는 미연결 상태다.

- Firebase Authentication 클라이언트 연동
- Google Drive, SNS, 주변 기기 공유의 실제 전송
- 독립 메모·결제·검색 자료·동영상·폴더 파일 첨부
- 해외 Google Map 전환과 iOS GPS 경로 렌더링
- 배터리 한도 설정의 실제 수집 정책 적용

### 3.2 MVP 제외 범위

- 상세 사용자 페르소나별 맞춤 흐름
- 자동 여행 일정 추천
- 실시간 사용자 간 공동 편집
- 여러 기기 간 실시간 동기화
- 독립적인 관리자 화면
- 지원 서비스가 확정되지 않은 자동 결제 메시지 수집

## 4. 사용자 인증

### 4.1 로컬 인증

앱 실행 또는 잠금 해제 시 다음 방식 중 사용자가 설정한 방법을 사용한다.

- 지문 또는 얼굴 인식
- PIN
- 비밀번호

로컬 인증은 기기 안의 자료를 보호하는 목적이며, Firebase 계정 식별을 대신하지 않는다.

앱이 백그라운드에서 연속 10분 이상 유지된 뒤 포그라운드로 복귀하면 로컬 인증을 다시 요구한다.

### 4.2 원격 인증

Firebase Authentication을 공통 인증 서버로 사용한다.

| 플랫폼 | 인증 방식 |
|---|---|
| Android | Google 계정, 이메일 링크 |
| iOS | Apple 계정, Google 계정, 이메일 링크 |

Firebase `uid`를 사용자 식별자로 사용하고, 사용자 데이터에 `uid`를 연결한다. Firebase SDK로 로그인 상태를 유지한다.

## 5. 핵심 기능 요구사항

### FR-01 앱 시작과 여행 생성

- 앱 실행 시 로컬 인증 설정을 확인한다.
- 최초 로그인 또는 원격 기능 사용 시 Firebase 인증을 수행한다.
- 국내 여행은 도시, 해외 여행은 나라를 선택한다.
- 사용자가 여행 시작일과 종료일을 지정한다.

### FR-02 자료 수집

- 사진·동영상은 촬영 시각, 장소, 파일 경로, 추가 메모를 수집한다.
- 현지 지도 저장 장소, 결제 장소, 사진·동영상 장소, 노트 작성 장소를 관련 장소로 우선 수집한다.
- 이동경로는 설정된 시간 간격의 GPS 위치 정보로 구성한다.
- 검색 자료는 시각, 장소, 종류, 제목, 요약, 출처를 저장한다.
- 결제 자료는 확인 가능한 범위에서 현지 시각, 가게, 구매 내용을 메모화한다.
- 날씨는 World Weather Information Service 또는 Yahoo Weather의 도시 날씨 정보를 사용할 수 있다.
- 수집 실패 자료는 실패 또는 사용자 확인 필요 상태로 남긴다.

### FR-03 메모

- 제목을 입력할 수 있다.
- 제목이 없으면 현지 시각 기준 날짜와 시간을 제목으로 표시한다.
- 내용을 입력하고 저장·수정할 수 있다.
- 사진첩과 폴더에서 사진·동영상·파일을 선택해 첨부할 수 있다.
- 배경색과 글꼴 등을 설정할 수 있다.

### FR-04 날짜별 경로 조회

- 여행과 날짜를 선택한다.
- 현지 지도에 해당 날짜의 이동경로를 표시한다.
- 경로에 사진, 동영상, 메모, 결제, 날씨 등의 정보 아이콘을 표시한다.
- 상단에 결제, 메모, 날씨 등 주요 활동을 표시한다.
- 아이콘을 선택하면 종류에 맞는 상세 정보를 팝업으로 표시한다.
- 여행기록 카드를 선택하면 사진·동영상은 큰 썸네일과 촬영시각·장소·메모를, 결제는 영수증 이미지와 결제시각·장소·메모를, 메모는 제목·작성시각·내용을 표시한다.
- 동일그룹 사진 여행카드는 메모 입력란과 같은 좌우 폭의 3열 썸네일을 정사각형 3×3 뷰포트로 표시하고, 추가 사진은 세로 드래그로 스크롤한다.
- 시작 카드는 당일 첫 GPS 좌표를 기준으로 10m 이상 이동한 첫 GPS 좌표의 위치와 작성시각을 표시하며, 해당 좌표가 없으면 첫 GPS 좌표를 사용한다. 종료 GPS 데이터는 지도 경로에 유지하지만 여행기록 목록에는 종료 카드를 표시하지 않는다.
- 팝업 하단에 저장·삭제·취소를 제공하며, 저장은 수정내용을 반영하고 삭제는 해당 카드만 삭제하며 취소는 변경을 버린다.
- 여행 기록 추가 팝업은 헤더 `...` 메뉴의 `추가`에서 열며, 첫 행에 메모·결제·사진 종류 선택을 표시하고, 다음 행에 제목·장소·메모를 상세 팝업과 동일한 입력 UI로 표시한다.
- 종류 선택 영역은 제목 입력란과 동일한 세로폭으로 표시하고 초기값은 메모로 한다.
- 여행기록 목록의 `+` 버튼은 제거하고 헤더 `...` 메뉴에서 삭제와 `추가`를 제공한다. 수정 아이콘은 표시하지 않는다.
- 추가 팝업은 첫 행에 생성 일자·시각을 `YYYY.MM.DD HH:mm` 형식으로 표시하고 저장 시 같은 시각을 기록한다.
- GPS 시작 카드는 제목을 `시작(년/월/일)` 형식으로 표시한다. 시작 카드의 메모가 비어 있으면 해당일 최고·최저 온도를 표시하고, 날씨 데이터가 없으면 비워 둔다. 종료 GPS 데이터는 지도 경로에만 사용한다.
- 시작 카드를 누르면 시작 카드는 유지한 채 해당 날짜의 나머지 여행카드와 날씨 카드를 숨기거나 다시 표시한다.
- 날짜가 접히면 해당 날짜의 지도 순번 마크도 숨기고, GPS 경로선은 유지한다. 다시 펼치면 마크를 복원한다.
- 여행기록은 기본 접힘 상태로 표시한다. 펼친 날짜가 하나면 해당 날짜의 경로에 맞춰 지도 범위를 조정하고, 여러 날짜면 해당 날짜들의 전체 경로에 맞춰 조정한다. 모든 날짜가 접혀 있으면 전체 경로를 표시한다. 경로 색상은 카드의 날짜 순번 색상보다 진하게 표시한다.
- 여행 중에는 오늘 날씨 카드를 목록 최상단에 항상 표시한다. 지난 여행에는 날씨 카드 대신 여행기간·도시·나라 요약을 표시하고, 계획 중인 여행에는 날씨 카드 대신 여권·숙소·항공권 준비 항목을 표시한다.
- 진행 중인 여행은 날씨 카드와 여행준비 카드를 같은 위치에 배치하고 좌우 swipe로 전환한다. 초기 페이지는 날씨 카드다.
- 여행준비 카드는 1행에 `여행준비`, 2행에 여권·숙소·항공권을 표시한다. 파일이 없으면 `+` 터치로 파일 선택창을 열고, 파일이 있으면 클립 아이콘 터치로 해당 파일을 뷰어에서 연다.
- 사진 상세 팝업에서 썸네일을 길게 누르면 선택 상태가 되고, `선택 삭제`로 해당 사진만 여행기록에서 숨긴다. 원본 갤러리 파일은 삭제하지 않는다.
- 선택 상태의 썸네일은 짧은 터치로 선택·선택 해제하며, 선택 상태가 아니면 짧은 터치로 갤러리 앱을 연다.
- 선택 상태의 썸네일은 짧은 터치로 선택·선택 해제하며, 선택 상태가 아니면 앱 내부 사진 갤러리 뷰어를 연다.
- 동일그룹 썸네일을 갤러리로 열면 그룹 전체 사진을 함께 전달해 선택 사진부터 좌우 swipe로 넘길 수 있다.
- 앱 내부 사진 갤러리 뷰어는 동일그룹 전체 사진을 `PageView`로 표시하고 선택 사진부터 좌우 swipe를 지원한다.
- 추가 팝업의 종류는 메모·결제·사진을 제공하며, 사진 선택 시 여행기간 갤러리에서 여러 장을 선택해 여행카드로 저장한다. 종류 선택과 제목·장소·메모 입력 영역은 밝은 파란색 배경을 사용한다.
- 헤더 `...` 선택 모드에서는 시작 카드와 사진·동영상·메모·결제 카드를 모두 선택 표시하며, 날씨 카드는 제외한다. 수동 기록도 삭제 대상에 포함한다. 시작 카드 선택은 표시만 제공하고 GPS 삭제 대상에는 포함하지 않는다.
- 선택된 시작 카드에는 수정 기능을 제공하며, 시작 카드는 삭제 대상에서 제외한다.
- 여행카드 순번은 사진 그룹과 수동 메모·결제를 포함해 계산하고, 지도 마커는 위치가 있는 사진 그룹만 같은 여행카드 순번으로 표시한다.
- 여행카드는 장소가 유효하면 제목 뒤에 `@장소`를 붙이고 장소만 해당 날짜 색상으로 표시하며, 장소가 NULL 또는 빈 값이면 제목만 표시한다.
- GPS 원본 좌표 목록은 일반 화면에 직접 노출하지 않는다.
- 지도는 핀치 확대·축소와 한 손가락 드래그를 지원한다.

### FR-05 과거여행 조회

- 과거여행 목록을 표시한다.
- 목록에는 `시작 년.월.일~종료 년.월.일` 형식의 여행 기간과 도시를 표시한다.
- 선택, 수정, 삭제 등의 편집 메뉴를 제공한다.
- 여행을 선택하면 전체 기간 동선을 현지 지도에 표시한다.
- 날짜별 동선은 서로 다른 색으로 표시한다.
- 특정 동선을 선택하면 날짜별 경로 조회 화면으로 이동한다.
- 진행 중 여행은 현재 위치 중심, 미래 여행은 국가·도시 중심으로 도시 규모에 맞춰 표시한다.
- 내 위치 버튼을 누르면 현재 위치 중심과 도시 규모로 다시 맞춘다.

### FR-06 여행 공유

- 여행 목록에서 공유할 여행을 선택한다.
- Google Drive, SNS, 주변 기기 공유를 제공한다.
- 주변 기기 공유는 Wi-Fi 또는 Bluetooth로 통신 가능한 기기를 대상으로 한다.
- 주변 기기 공유는 동일 앱이 설치된 수신 기기를 대상으로 한다.
- 수신 기기가 공유를 동의한 뒤 전송을 시작한다.
- 다른 기기에서 조회할 수 있도록 선택한 여행의 모든 수집 데이터를 전달한다.
- 수신 기기에서는 과거여행 조회 기능으로 공유받은 여행을 확인한다.

### FR-07 앱 설정

- 백그라운드 위치 수집 정책과 배터리 사용 한도를 표시한다.
- 위치 정보 수집 간격을 설정한다.
- Google Drive 연동 정보를 입력·수정한다.
- SNS 공유 연동 정보를 입력·수정한다.
- 인증 정보는 일반 메모와 로그에 기록하지 않는다.

### FR-08 여행 사진 메타데이터

- 여행기간의 사진을 사진첩에서 조회해 grid로 표시한다.
- 여행 상세 화면에 진입하거나 앱으로 복귀하면 여행기간의 새 사진을 자동으로 동기화해 여행카드를 생성한다.
- 사진의 현지 촬영시각·장소·원본 파일 경로를 메타데이터로 저장한다.
- 메타데이터 삭제는 원본 사진을 삭제하지 않으며, 삭제된 사진은 해당 여행 화면에서 숨긴다.
- 사진 기능 사용 시 운영체제의 사진 접근 권한을 요청한다.

### FR-09 디버그 로그

- 각 기능의 처리 결과를 기록한다.
- 디버그 모드에서만 로그 화면과 기록을 활성화한다.
- 비밀번호, 토큰, 원본 메시지, 개인정보가 포함된 파일 경로를 기록하지 않는다.

## 7. 기술 구성

| 영역 | 기술 또는 기준 |
|---|---|
| 공통 앱 | Flutter + Dart |
| 상태·화면 | Flutter 기본 API 우선 사용 |
| Android 전용 | Kotlin, Gradle, Android 권한·백그라운드 API |
| iOS 전용 | Swift, Xcode, iOS 권한·백그라운드 API |
| 지도 | 현지 지도 연동: 국내 카카오지도, 국외 Google Map |
| 위치 | Flutter 플러그인 우선, 부족하면 Kotlin·Swift 브리지 |
| 원격 인증 | Firebase Authentication |
| 로컬 인증 | 생체인증·기기 PIN·비밀번호 API |
| 테스트 | `flutter analyze`, `flutter test`, Android·iOS 실기기 테스트 |

플랫폼 공통 코드는 Flutter로 유지하고, 운영체제 기능 때문에 필요한 경우에만 네이티브 코드를 추가한다.

현재 Android 구현은 `kakao_maps_flutter`를 로컬 패키지로 사용하며, 지도 생성 시 기본 마커 레이어를 초기화한 뒤 기록 마커와 네이티브 ShapeLayer 폴리라인을 추가한다. 이 초기화 순서가 보장되지 않으면 마커 예외가 경로 렌더링을 중단하므로 지도 구현의 필수 순서로 취급한다. Flutter 앱은 현재 로컬 저장만 사용하고, `backend/`의 Firebase ID 토큰 검증·Firestore API는 독립 실행 가능한 후속 연동 대상으로 둔다.

## 8. 비기능 요구사항

### NFR-01 동시 접속

원격 인증과 공유 기능을 포함한 서버 측 사용량은 1,000명 동시 접속을 목표로 한다. 실제 달성 여부는 출시 전 인증·공유 흐름의 부하 테스트로 확인한다.

### NFR-02 오프라인 동작

로컬에 저장된 여행 자료의 조회와 메모 작성은 네트워크가 없어도 가능한 범위에서 동작한다. 원격 인증과 외부 공유 실패는 자료 손실 없이 재시도 가능한 상태로 표시한다.

### NFR-03 보안과 개인정보

- 최소 권한만 요청한다.
- 위치·결제·미디어 자료의 수집 목적과 범위를 사용자에게 알린다.
- 인증 정보와 민감한 원본 자료를 로그에 남기지 않는다.
- 사용자별 데이터는 Firebase `uid`와 권한으로 구분한다.
- 로컬 자료를 삭제할 때 사용자 확인을 제공한다.

### NFR-04 접근성

- 인증을 통과한 사용자가 설치된 앱에 접근할 수 있어야 한다.
- 충분한 터치 영역과 읽을 수 있는 글자 크기를 사용한다.
- 색상만으로 정보 종류나 상태를 구분하지 않는다.

## 9. 일정과 우선순위

1인 개발자가 2일 안에 핵심 기능을 완성하는 것을 기준으로 한다.

| 우선순위 | 2일 내 목표 |
|---|---|
| P0 | 앱 실행, 로컬·원격 인증 기본 흐름, 여행 생성, 로컬 저장, 날짜별 경로 조회의 기본 흐름 |
| P1 | 과거여행 목록, 메모, 활동 아이콘, 설정 화면 |
| P2 | Google Drive·SNS·주변 기기 공유, 자동 수집 확장 |

P0를 먼저 검증하고, P1·P2는 실제 연동 난이도와 플랫폼 제약에 따라 범위를 조정한다. 2일 내 모든 외부 연동을 완성한다고 가정하지 않는다.
