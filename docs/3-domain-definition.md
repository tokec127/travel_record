## 1. 문서 목적

여행 중 여러 앱에서 생성되는 자료를 여행 단위로 모아 시간과 장소를 기준으로 조회하기 위한 도메인 범위를 정의한다.

이 문서는 화면 설계나 특정 저장소·외부 서비스의 구현 방법을 정하지 않는다. 구현 시 필요한 핵심 데이터와 사용자 흐름의 기준으로 사용한다.

## 2. 문제와 목표

### 2.1 문제

사진, 동영상, 검색 결과, 메모, 결제, 날씨, 이동경로가 서로 다른 앱에 흩어져 있어 여행의 맥락으로 함께 확인하기 어렵다.

### 2.2 목표

- 여행별로 수집 자료를 묶는다.
- 자료에 발생 시각과 장소를 연결한다.
- 날짜별 이동경로와 활동 자료를 한 화면에서 확인한다.
- 이동경로의 특정 위치에서 관련 자료를 상세 조회한다.
- 수집과 처리 결과를 디버그 모드에서만 추적한다.

## 3. 도메인 범위

### 3.1 포함 범위

| 영역 | 설명 |
|---|---|
| 여행 | 사용자가 자료를 모으는 기간과 장소의 단위 |
| 이동경로 | 시간순 위치 기록과 날짜별 경로 |
| 활동 기록 | 특정 시각·장소에서 발생한 결제, 방문, 검색, 메모 등 |
| 미디어 | 사진과 동영상의 파일 경로 및 메타데이터 |
| 메모 | 사용자가 작성하거나 수집 자료를 요약한 텍스트 |
| 외부 정보 | 명소, 식당, 아이템, 뉴스, 날씨 등 검색·수집 정보 |
| 로그 | 기능 처리 결과를 디버그 모드에서 확인하기 위한 기록 |
| 권한 | 위치, 사진·동영상, 알림·메시지 등 기능별 접근 허용 상태 |

### 3.2 제외 또는 확인 필요 범위

- 인증 제공자와 계정 연동 방식은 `5.11 인증(Authentication)`에 정의한다.
- 현지 지도는 국내에서 카카오지도, 국외에서 Google Map을 사용한다. 각 지도 API의 구체적인 요금·키 관리 방식은 별도로 정한다.
- 결제 메시지와 검색 자료를 어떤 운영체제 API 또는 외부 연동으로 수집할지는 별도 검토가 필요하다.
- 실시간 다기기 동기화와 자동 백업은 MVP 범위에서 제외한다. 선택한 여행의 일회성 공유는 MVP 범위에 포함한다.
- 현재 백엔드는 Firebase Authentication ID 토큰을 검증하고 Firestore에 여행·GPS·사진 메타데이터·공유 세션을 저장하는 API를 제공한다. Flutter 클라이언트 연결과 실제 외부·주변 기기 전송은 후속 범위다.

여행 자료를 수집하고, 날짜별 경로와 활동 기록을 조회하며, 메모를 작성하는 사람이다.

### 4.2 외부 시스템

| 현지 지도 서비스 | 국내 카카오지도, 국외 Google Map을 통한 지도 표시, 장소 검색, 경로 시각화 |

## 5. 핵심 도메인 모델

### 5.1 여행(Trip)

자료를 묶는 최상위 단위다.

| 속성 | 설명 |
|---|---|
| 식별자 | 여행을 구분하는 값 |
| 제목 | 사용자가 알아보기 위한 여행 이름 |
| 시작·종료 시각 | 여행 기간. 현지 기준으로 표시 |
| 기준 지역 또는 시간대 | 날짜와 시각을 해석하는 기준 |
| 상태 | 진행 중, 종료 등 최소 상태 |

앱은 사용자가 인증하는 것으로 시작한다. 인증 후 사용자는 여행의 시작과 끝을 정하며, 국내 여행은 도시 기준으로, 해외 여행은 나라 기준으로 여행 범위를 결정한다.

모든 이동경로와 활동 기록은 하나의 여행에 속한다. 여행에 직접 연결할 수 없는 자료는 별도 보류 상태가 필요할 수 있으나, MVP에서는 사용자 확인 대상으로 표시한다.

### 5.2 이동경로(Route)

특정 여행의 특정 날짜 또는 시간 구간에 대한 위치 흐름이다.

| 속성 | 설명 |
|---|---|
| 식별자 | 경로 구분 값 |
| 여행 식별자 | 소속 여행 |
| 기준 날짜 | 현지 날짜 |
| 위치 기록 | 시각, 위도, 경도, 정확도 등 |
| 시작·종료 시각 | 경로가 기록된 시간 범위 |

위치 기록은 원본 좌표 목록으로 일반 화면에 직접 나열하지 않는다. 현지 지도에서는 기록된 현지 날짜별로 경로를 분리하고 서로 다른 색상의 선으로 표시한다. 지도 이동·핀치 확대·축소가 발생하면 현재 화면 좌표로 경로를 다시 배치하며, 같은 시간·장소에 연결된 활동 기록은 지도 아이콘으로 표시한다.

### 5.3 활동 기록(Activity)

여행 중 발생한 사건을 공통 형식으로 표현한다. 활동 종류에 따라 상세 데이터가 달라진다.

| 공통 속성 | 설명 |
|---|---|
| 식별자 | 활동 구분 값 |
| 여행 식별자 | 소속 여행 |
| 발생 시각 | 활동이 발생한 현지 시각 |
| 장소 | 좌표, 장소명 또는 주소. 확보된 범위만 저장 |
| 종류 | 미디어, 메모, 결제, 검색, 날씨, 방문 등 |
| 제목 또는 요약 | 목록과 상단 주요 활동에 표시할 내용 |
| 출처 | 사용자 입력, 운영체제, 외부 서비스 등 |
| 수집 상태 | 수집됨, 처리 실패, 사용자 확인 필요 등 |

활동 기록은 지도 아이콘과 상세 팝업의 공통 대상이다. 종류별 상세 정보는 아래 자료를 참조한다.

### 5.4 미디어(Media)

사진 또는 동영상 파일을 표현한다.

- 파일 경로 또는 접근 가능한 로컬 식별자
- 미디어 종류
- 촬영 시각
- 촬영 위치
- 추가 메모
- 연결된 활동 기록

여행기간에 촬영한 사진은 그리드로 표시하고, 사용자가 선택한 사진만 촬영 현지 시각·장소·파일 위치 메타데이터로 관리한다. 메타데이터 삭제 시 원본 사진은 유지하며 해당 사진은 앱의 여행 화면에서 다시 표시하지 않는다.

여행 기록 조회 화면은 사진·동영상 항목을 큰 썸네일과 촬영 시각·장소·파일 위치·메모의 2컬럼으로 표시한다. 여행 종료 위치는 여행 종료일이 지난 뒤에만 표시하며, 날씨 요약 또는 수집되지 않은 상태를 함께 표시한다. 항목 선택 후 메모 수정 또는 메타데이터 삭제를 제공하고 원본 미디어는 삭제하지 않는다.

날씨 카드를 제외한 여행기록 카드는 발생 시각순으로 순번을 부여한다. 순번 원형은 여행 시작일로부터의 날짜에 따라 다른 색을 사용하고, 현지 지도상의 해당 발생 위치에도 같은 날짜 색상을 사용한다. 카드 안쪽의 위·아래 여백은 두지 않으며, 카드에는 순번, 대표그림, 상단 제목·시각, 하단 메모를 표시한다. 각 날짜의 첫 GPS 기록은 순번 대신 `S`, 마지막 GPS 기록은 순번 대신 `E`를 표시하고 대표그림에는 시간대 아이콘을 사용한다. 시작·종료 카드의 하단 메모는 사용자가 입력한 GPS 메모이며 없으면 공백으로 표시한다.

사진·동영상은 촬영시각순으로 정렬한다. 현재 자료와 바로 이전 자료의 촬영 장소가 100m 이내이고 시각 차이가 30분 이내이면 같은 그룹으로 보고, 그룹의 첫 자료만 여행카드 대표그림으로 표시한다. 대표그림에는 그룹에 포함된 사진 수를 함께 표시한다. 그룹 전체 메타데이터와 원본 파일은 로컬 저장소에 유지한다. 동영상은 첫 화면 썸네일 위에 재생 아이콘을 표시한다. 결제 영수증과 독립 메모 카드는 해당 데이터 모델이 저장될 때 각각 영수증·메모 아이콘을 대표그림으로 사용한다.

여행 기록 상단의 `+` 아이콘으로 결제 또는 메모 종류, 제목, 메모를 입력한다. 저장 시 입력 시각으로 순번 카드가 생성되고, 결제는 영수증 아이콘, 메모는 메모 아이콘을 대표그림으로 사용한다. 사진 그룹 대표 카드를 선택하면 그룹에 속한 사진을 팝업 안에 96×96px 고정 썸네일 묶음으로 표시하고 가용 폭에 따라 자동 줄바꿈한다. 그룹 팝업은 본문이 사라지지 않도록 내부 스크롤 grid를 사용하지 않는다.

기록 항목을 선택하면 상세 팝업을 표시한다. 사진·동영상 항목은 팝업에서 사용자 메모를 추가·수정하거나 메타데이터를 삭제할 수 있으며, 저장·삭제 결과는 팝업을 닫은 직후 여행 기록 목록에 반영한다.

팝업 하단에는 저장·삭제·취소 버튼을 표시한다. 시작·종료 위치는 자동 수집된 위치와 작성시각을 표시하고, 사진·동영상은 큰 썸네일·촬영시각·장소·메모를 표시한다. 결제와 독립 메모 팝업은 해당 데이터 모델이 연결될 때 영수증 또는 제목·내용 필드를 추가한다.

파일 자체와 메타데이터는 구분한다. 파일을 사용할 수 없더라도 메타데이터나 처리 실패 상태는 데이터 손실을 방지하기 위해 별도로 남길 수 있다.

### 5.5 메모(Note)

사용자가 직접 작성한 글 또는 수집 자료에서 생성된 요약이다.

- 제목: 사용자가 입력한다. 제목이 없으면 현지 시각 기준의 날짜와 시간으로 표시한다.
- 내용: 사용자가 메모 내용을 입력할 수 있다.
- 저장·수정: 입력하거나 수정한 메모를 저장하고 수정할 수 있다.
- 첨부: 사진첩 또는 폴더에서 사진·동영상·파일을 선택해 첨부할 수 있다.
- 설정: 메모의 배경색과 글꼴 등을 설정할 수 있다.
- 작성·수집 시각
- 장소
- 사용자 작성인지 자동 요약인지 나타내는 출처
- 연결된 검색, 결제, 미디어 또는 방문 기록

자동 요약은 원본 자료를 대체하지 않는다. 요약 실패 시 원본 활동 기록을 조회할 수 있어야 한다.

### 5.6 외부 정보(Reference)

사용자가 검색하거나 조회한 현지 정보를 표현한다.

- 정보 종류: 명소, 식당, 아이템, 뉴스, 날씨 등
- 제목과 요약
- 원문 또는 외부 참조 주소
- 검색·조회 시각
- 관련 장소
- 원본 출처
- 생성된 요약 메모와의 연결
- 사용자 승인에 따라 선택한 날짜 기준으로 수집 자료와 메타데이터를 로컬에 저장
- 로컬에 저장된 자료를 추후 조회하고 공유하는 기능
- 관련 장소는 현지 지도의 저장 장소, 결제 장소(가게), 사진·동영상 촬영 장소, 노트 작성 장소를 우선 수집
- 이동경로는 설정된 시간 간격에 따라 수집한 GPS 위치 정보로 구성

외부 정보는 조회 시점에 따라 내용이 달라질 수 있으므로 수집 시각과 출처를 함께 보존한다.

### 5.7 결제 기록(Payment)

결제 관련 메시지에서 추출한 현지 결제 정보다.

- 결제 시각
- 장소 또는 가맹점
- 구매 내용
- 금액과 통화. 확인된 경우에만 저장
- 원본 메시지에 대한 안전한 참조 또는 처리 상태
- 사용자가 수정한 메모

민감한 원본 메시지와 전체 결제 정보는 로그에 기록하지 않는다. 메시지 접근과 저장은 사용자의 명시적 권한과 플랫폼 지원 범위 안에서만 처리한다.

### 5.8 날씨 기록(Weather)

특정 시각과 장소의 날씨 정보다.

날씨 정보는 `World Weather Information Service`를 활용하거나 `Yahoo Weather`에서 제공하는 도시 날씨 정보를 사용할 수 있다. 과거 여행일은 과거 날씨 자료를 조회해 날짜별로 로컬 저장하고, 시작·종료 카드 대표그림은 해당 날짜의 오전·오후 날씨 상태를 사용한다.

- 관측 또는 조회 시각
- 장소
- 기온, 상태 등 제공된 값
- 외부 서비스 출처

날씨는 활동 기록에 연결하여 주요 활동이나 지도 팝업에서 조회한다.

### 5.9 디버그 로그(DebugLog)

기능 수행 결과를 개발 중 확인하기 위한 기록이다.

- 기록 시각
- 기능명
- 처리 결과
- 오류 유형과 안전한 요약
- 관련 자료 식별자

디버그 로그 화면과 기록은 디버그 모드에서만 활성화한다. 비밀번호, 인증 토큰, 원본 메시지, 미디어 경로에 포함된 개인정보 등 민감한 값은 남기지 않는다.

### 5.10 앱 설정(AppSettings)

앱 전체에서 적용되는 수집 및 연동 설정이다.

- 백그라운드 위치 수집 정책과 배터리 사용 한도 표시
- 위치 정보 수집 간격 설정
- `Google Drive` 연동 정보 입력
- SNS 공유를 위한 연동 정보 입력

Google Drive와 SNS 연동 정보는 인증 정보가 포함될 수 있으므로 일반 메모나 디버그 로그에 저장하지 않는다. 실제 지원 서비스와 인증 방식은 구현 전에 확정한다.

### 5.11 인증(Authentication)

앱은 로컬 인증과 원격 인증을 구분한다.

| 구분 | 목적 | 방식 |
|---|---|---|
| 로컬 인증 | 앱 실행과 잠금 해제 | 지문·Face ID 등 생체인증, PIN, 비밀번호 |
| 원격 인증 | 사용자 계정 식별과 데이터 연동 | Firebase Authentication |

원격 인증 방식은 플랫폼별로 다음을 사용한다.

- Android: Google 계정, 이메일 링크
- iOS: Apple 계정, Google 계정, 이메일 링크

원격 인증 결과의 사용자 식별자는 Firebase `uid`를 사용한다. 로그인 상태는 Firebase SDK가 유지하며, 사용자 데이터에는 `uid`를 연결한다. Google Drive 또는 SNS 공유 시에도 사용자 식별과 접근 권한 확인에 `uid`를 사용한다.

### 5.12 현재 구현 매핑

현재 앱이 실제로 저장·조회하는 로컬 모델은 `Trip`, `RoutePoint`, `PhotoMetadata`, `WeatherRecord`, `ManualRecord`다. `Activity`, `ShareSession`은 제품 범위와 백엔드 논리 모델에는 정의되어 있으나 Flutter 화면과 로컬 모델에는 아직 연결하지 않았다.

| 기능 | 현재 구현 | 미연결 또는 후속 범위 |
|---|---|---|
| 인증 | Android 로컬 생체인증 및 기기 PIN 대체 인증 | Firebase Authentication 클라이언트 연동, iOS 실기기 검증 |
| 저장 | `SharedPreferencesAsync` 기반 여행 JSON 저장 및 저장 큐·병합 | 암호화 저장, 원격 동기화 |
| 지도 | Android 카카오지도, 네이티브 ShapeLayer 폴리라인·마커, 자동 bounds | 해외 Google Map 전환, iOS 경로 폴리라인 |
| 위치 | 권한 확인, 설정 간격(기본 10분) 백그라운드 수집, 여행별 GPS 저장 | 배터리 한도 설정 화면의 실제 적용 |
| 사진 | 사진첩 기간 필터·grid, 사진 메타데이터 저장·숨김 | 동영상·폴더 파일 첨부의 전체 흐름 |
| 결제·메모 카드 | `ManualRecord` 입력·수정·삭제, 로컬 저장, 대표 아이콘 | 영수증 원본 첨부·결제 자동 수집 |
| 날씨 | WWIS 도시 목록·일별 저장, 과거 Open-Meteo 자료와 당일 현재 날씨 보완, 시작·종료 시간대 날씨 아이콘 | Yahoo Weather 선택 연동 |
| 공유 | 백엔드 공유 세션 API의 도메인·상태 모델 | Google Drive·SNS·Wi-Fi/Bluetooth 실제 전송 |

## 6. 관계와 조회 기준

```text
사용자 1 ── N 여행
사용자 1 ── 1 앱 설정
여행 1 ── N 이동경로
여행 1 ── N 활동 기록
여행 1 ── N 공유 세션
활동 기록 1 ── 0..1 미디어/메모/외부 정보/결제/날씨 상세
이동경로 1 ── N 위치 기록
이동경로의 위치 기록 ── 시간·장소 기준 ── 활동 기록
```

자료를 묶는 기본 키는 `여행 식별자`이고, 지도와 날짜 화면의 연결 기준은 `현지 시각`과 `장소`다. 위치가 없거나 정확도가 낮은 자료는 시간 기준으로 먼저 연결하고, 사용자에게 연결 상태를 표시한다.

## 7. 주요 사용자 흐름

### 7.1 앱 시작

1. 앱 실행 시 설정된 로컬 인증으로 잠금을 해제한다.
2. 최초 로그인이나 원격 기능 사용 시 Firebase Authentication으로 인증한다.
3. 국내 여행은 도시를, 해외 여행은 나라를 선택하고 여행의 시작과 끝을 정한다.
4. 필요한 권한의 현재 상태를 확인한다.
5. 사용자가 허용한 범위에서 위치, 미디어, 메시지 등의 자료 수집을 시작한다.
6. 수집 결과를 여행과 활동 기록으로 저장한다.
7. 처리 결과를 디버그 모드에서만 로그로 남긴다.

### 7.2 날짜별 경로 조회

1. 사용자가 여행과 날짜를 선택한다.
2. 해당 날짜의 이동경로를 지도에 표시한다.
3. 경로 주변의 활동 기록을 종류별 아이콘으로 표시한다.
4. 상단에는 결제, 메모, 날씨 등 주요 활동을 요약한다.
5. 아이콘을 선택하면 해당 상세 정보를 팝업으로 표시한다.

지도 초기 화면은 여행 상태에 따라 자동 조정한다. 진행 중 여행은 현재 위치와 도시 규모, 과거 여행은 저장 경로와 도시 규모, 미래 여행은 선택한 국가·도시 중심과 도시 규모를 기준으로 한다. 사용자는 핀치로 확대·축소하고 한 손가락 드래그로 이동할 수 있으며, 내 위치 버튼을 누르면 현재 위치 중심으로 재조정한다.

### 7.3 자료 수집과 요약

1. 자료의 원본 시각과 장소를 확인한다.
2. 자료 종류에 맞는 활동 기록을 생성한다.
3. 검색 자료는 제목, 요약, 출처, 시각, 장소를 저장한다.
4. 결제 메시지는 현지 시각, 가맹점, 구매 내용을 추출해 메모화한다.
5. 처리할 수 없는 자료는 조용히 버리지 않고 실패 또는 사용자 확인 필요 상태로 남긴다.

### 7.4 과거여행 조회

과거여행 조회 메뉴에서 저장된 여행을 목록으로 확인하고 관리한다.

#### 여행 목록

- 여행 기간을 `시작 년.월.일~종료 년.월.일` 형식으로 표시한다.
- 여행 도시를 표시한다.
- 목록 하단에 선택, 수정, 삭제 등의 편집 메뉴를 표시한다.

#### 여행 선택

1. 선택한 여행의 전체 기간 동선을 현지 지도에 표시한다.
2. 날짜별 동선은 서로 다른 색으로 구분한다.
3. 특정 동선을 선택하면 날짜별 경로 조회 화면을 표시한다.
4. 날짜별 경로 조회 화면의 이후 동작은 `7.2 날짜별 경로 조회`와 동일하게 처리한다.
5. 화면 하단에 선택, 수정, 삭제 등의 편집 메뉴를 표시한다.

#### 여행 공유

- 여행 목록을 표시하고 공유할 여행을 선택할 수 있다.
- 공유 방식으로 `Google Drive`, SNS, 주변 기기 공유를 제공한다.
- 주변 기기 공유는 Wi-Fi 또는 Bluetooth로 통신 가능한 기기를 대상으로 한다.
- 주변 기기 공유의 전제조건은 수신 기기에 동일한 앱이 설치되어 있는 것이다.
- 동일 앱이 설치된 주변 기기가 수신에 동의하면 공유를 시작한다.
- 공유 데이터에는 다른 기기에서 여행을 조회할 수 있도록 모든 수집 데이터를 포함한다.
- 수신한 기기에서는 과거여행 조회 기능을 통해 공유받은 여행 정보를 조회할 수 있다.

### 7.5 앱 전체 설정

1. 사용자가 앱 전체 설정 메뉴를 연다.
2. 백그라운드 위치 수집 정책과 배터리 사용 한도를 확인한다.
3. 위치 정보 수집 간격을 설정한다.
4. `Google Drive`와 SNS 공유에 필요한 연동 정보를 입력하고 저장한다.

## 8. 권한과 개인정보 원칙

| 권한 | 사용 목적 | 요청 시점 |
|---|---|---|
| 위치 | 이동경로와 자료 장소 수집 | 경로 기록 기능을 시작할 때 |
| 사진·동영상 | 미디어 메타데이터와 파일 조회 | 미디어 수집 기능을 사용할 때 |
| 메시지·알림 | 결제 관련 메시지 확인 | 해당 자동 수집 기능을 켤 때 |
| 알림 등 기타 권한 | 실제 기능이 확정된 경우에만 사용 | 해당 기능 사용 직전 |

권한을 거부해도 앱의 다른 기록과 조회 기능은 가능한 범위에서 사용할 수 있어야 한다. 위치와 결제 정보는 민감 정보이므로 수집 범위, 보존 방식, 삭제 동작을 구현 전에 확정한다.

## 9. MVP 경계와 후속 결정

### 9.1 MVP에 필요한 기능

- 여행과 날짜 선택
- 과거여행 목록과 여행 편집
- 앱 전체 설정
- 이동경로 조회
- 활동 기록의 공통 목록과 종류 구분
- 사진·동영상·메모 상세 팝업
- 수집 시각·장소 저장
- 권한 거부와 수집 실패 상태 표시
- 디버그 모드 로그 확인

### 9.2 후속 결정이 필요한 항목

- Firebase 데이터 저장소와 동기화 범위
- 현지 지도 서비스와 API 사용 방식
- 백그라운드 위치 수집 정책과 배터리 한도
- Android와 iOS의 메시지 접근 가능 범위
- 자동 요약 처리 방식과 비용
- 여행·자료 삭제 및 백업 정책
